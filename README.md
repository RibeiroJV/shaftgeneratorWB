# Axis Generator — FreeCAD Workbench

## Recent fixes (this version)

- **Cosmetic thread is now a lightweight visual indicator, not a
  boolean-cut geometry feature.** An earlier iteration cut a real
  V-groove ring per pitch into the solid — geometrically correct, but a
  boolean cut per tooth is exactly the kind of operation that makes
  recompute grind to a halt once a shaft has more than a couple of
  threaded segments (or a fine pitch on a long segment, i.e. hundreds of
  rings). `HasThread` now leaves the solid itself untouched — a plain
  cylinder, cheap to recompute regardless of pitch or length — and adds
  a **cosmetic helix curve** (crest + root, no material removed) purely
  so a threaded segment reads as "threaded" in the 3D view, on top of
  the colour change that was already there. A new `ShowThreadIndicator`
  property lets you turn that curve off entirely if it's ever visual
  clutter; the optional DIN 76 exit groove (`HasThreadExitGroove`) is
  still a real single cut, since one cut per segment is cheap either way.
  There is only one thread "style" now — the earlier README mention of
  a second "Real (hélice)" helical-sweep style was aspirational and was
  never actually implemented, so that language has been removed.
- **The 2D drawing's thread indication is unaffected by any of this.**
  `Gerar Desenho 2D (TechDraw)` draws its ISO 6410 minor-diameter lines,
  thread-limit line, and `M8x1.25`-style legend straight from each
  segment's `Diameter`/`ThreadPitch`/`ThreadExtent`/etc. properties —
  it never depended on the 3D cut geometry, so it works the same
  whether or not the 3D indicator above is switched on.
- **Renaming a segment by hand now sticks.** `Axis.execute()` used to
  overwrite every segment's tree `Label` on every recompute, so a manual
  rename got silently reverted the next time anything changed. Each
  segment now remembers its own last auto-generated label (`AutoLabel`,
  hidden) and only refreshes `Label` while the two still match; once you
  rename a segment yourself, it's left alone.
- **Removed `AxisTechDraw.py`.** It implemented a more advanced
  auto-dimensioning/callout system (tiered dimensions, groove/keyway
  leaders, section-cut views) but was never imported or called from
  anywhere, and would have raised `AttributeError` the moment it ran —
  it set a custom `AutoGeneratedByAxis` attribute directly on stock
  FreeCAD types without registering it via `addProperty` first. It's
  been deleted rather than left in half-working; the simpler ISO 6410
  thread-line overlay in `AxisGeneratorCmds.py` (`Gerar Desenho 2D`) is
  the one TechDraw feature that's actually wired up and working.

- **Toolbar/menu icons now show up.** The old code pointed at FreeCAD's
  built-in Qt resource paths (`:/icons/Part_Cylinder.svg`,
  `:/icons/TechDraw_PageDefault.svg`, `:/icons/draw-arrow-back.svg`,
  etc.). Several of those aliases aren't guaranteed to exist under every
  FreeCAD version/icon theme, which is why they rendered blank. This
  version ships its own small SVGs under `Resources/icons/` and resolves
  them with an absolute filesystem path (see `AxisIcons.py`), so the
  segment/thread/TechDraw/reorder command icons work the same on every
  install. Feel free to swap any of these `.svg` files for your own
  artwork later — the filenames are all that matter.
  - The one exception is the **workbench selector icon** itself (the icon
    next to "Axis Generator" in the workbench dropdown). FreeCAD evaluates
    `MenuText`/`ToolTip`/`Icon` at class-body level in a stripped-down
    context with no imports, no `os`, and no `__file__` available — any
    computed path there raises a startup error ("name 'AxisIcons' is not
    defined", or "name '__file__' is not defined"). That attribute has to
    stay a plain, dependency-free literal, so it's kept on a standard
    built-in FreeCAD resource (`:/icons/Std_Part.svg`) rather than one of
    our bundled files.
- **TechDraw thread indication now actually appears.** The 2D generator
  was calling `DrawViewPart.makeCosmeticLine(p1, p2)` with raw 3D model
  coordinates, but that method expects points already expressed in the
  view's own 2D page coordinate system — so the lines landed off-page or
  degenerate and nothing visible was produced. The fix uses
  `makeCosmeticLine3d(p1, p2)`, which is built to take 3D model-space
  points and project them through the view's own Direction/XDirection/
  Scale. The generated drawing now shows, per ISO 6410 convention: the
  minor-diameter (root) lines along the threaded length, a thread-limit
  line where a partial thread stops inside a segment, and a text legend
  listing each thread's designation (e.g. `M8x1.25`).
- **"Could not read the new template file" is fixed.** The 2D generator
  hardcoded `A4_Landscape_TD.svg` as the TechDraw page template filename.
  FreeCAD has renamed/reorganized its bundled template files across
  versions (FreeCAD 1.1 ships different names than older releases), so a
  hardcoded filename can silently stop existing on a given install. The
  command now scans the real `Mod/TechDraw/Templates` folder on your
  install and picks the best-matching A4 landscape template automatically,
  so it keeps working across FreeCAD versions.

  would; the code just wasn't doing it).
- Threaded segments now show their `M`-designation right in the tree
  label, so you can see at a glance which step is threaded without
  opening the property editor.


Build a stepped axle/shaft as a stack of cylindrical diameter segments,
where **each diameter is its own object (body) in the Model tree**, and
**dragging a segment up/down in the tree re-orders it along the axis**.

## How it works

- **Axis** is a container object. It holds an ordered list of children
  (the native FreeCAD "Group" — the same mechanism used by `Std::Group`
  / `App::Part`), so it fully supports normal tree drag-and-drop.
- **Segment** is one diameter step: a simple cylinder defined by
  `Diameter` and `Length`.
- On every recompute, the Axis walks its children **in tree order** and
  places each one immediately after the previous one along local Z.
  Its `StartOffset` property is updated to reflect where it now starts.
- Dragging a Segment to a new position inside the Axis in the tree
  changes the Group order, which the Axis proxy detects (`onChanged`)
  and immediately recomputes — so the geometry re-stacks live.

## Install

1. Find your FreeCAD user `Mod` folder:
   - Linux: `~/.local/share/FreeCAD/Mod/`
   - Windows: `%APPDATA%\FreeCAD\Mod\`
   - macOS: `~/Library/Preferences/FreeCAD/Mod/`
   (Create the `Mod` folder if it doesn't exist.)
2. Copy the whole `AxisGenerator` folder into that `Mod` folder, so you end
   up with `.../Mod/AxisGenerator/InitGui.py` etc.
3. Restart FreeCAD.
4. Open the workbench dropdown (top toolbar) — "Axis Generator" should
   now be listed.

## Usage

1. Switch to the **Axis Generator** workbench.
2. Click **New Axis** to create an empty container (or just click
   **Add Diameter Segment** — it will create one for you automatically).
3. Click **Add Diameter Segment**. You'll be asked for the
   cross-section (**Circular**, **Quadrado** or **Hexagonal**), its size
   (diameter / side / distance across flats), and its length. Repeat for
   each step of the shaft — each new segment is appended at the bottom
   of the stack.
4. In the Model tree, **drag a Segment up or down** within its Axis to
   change where that step sits along the shaft — the 3D geometry
   updates immediately.
5. Alternatively, select a single Segment and use **Move Segment
   Up / Move Segment Down** (Axis Generator menu or toolbar) to reorder
   it without dragging.
6. Select a Segment and use the **property editor** to fine-tune it —
   grouped into `Segment`, `Chaveta`, `Canal` and `Rosca` categories
   (only the fields relevant to the current settings are shown; the
   rest are hidden until you enable the checkbox above them):

   | Group     | Property (PT)          | What it does |
   |-----------|-------------------------|--------------|
   | Segment   | `ProfileType`           | Circular / Quadrado / Hexagonal |
   | Segment   | `Diameter` / `Width` / `AcrossFlats` | size for the chosen profile |
   | Segment   | `Length`                | length of this step |
   | Chaveta   | `HasKeyway`             | turn the keyway on/off |
   | Chaveta   | `KeywayWidth` (Largura), `KeywayDepth` (Profundidade), `KeywayLength`, `KeywayPosition` (Posição), `KeywayAngle` | keyway slot geometry & where it sits |
   | Canal     | `HasGroove`             | turn the circumferential groove on/off |
   | Canal     | `GrooveWidth` (Largura), `GrooveDepth` (Profundidade), `GroovePosition` (Posição) | groove geometry & position (Circular profile only) |
   | Rosca     | `HasThread`             | turn the external thread on/off |
   | Rosca     | `ThreadPitch`, `ThreadExtent` (Total/Parcial), `ThreadLength`, `ThreadSide` (Início/Fim) | thread pitch, extent, and which side a partial thread starts on (Circular profile only) |
   | Rosca     | `ShowThreadIndicator`   | show/hide the cosmetic helix curve in the 3D view |
   | Rosca     | `HasThreadExitGroove`, `ThreadExitGrooveWidth`, `ThreadExitGrooveDepth` | optional DIN 76-style relief groove at the thread's run-out end |

7. The Axis object's read-only `TotalLength` property shows the overall
   shaft length; each Segment's read-only `StartOffset` shows where it
   begins.

## Keyways, grooves and threads — details

- **Chaveta (keyway)**: cut radially into the outer surface, `KeywayWidth`
  wide and `KeywayDepth` deep, starting at `KeywayPosition` along the
  segment and running for `KeywayLength`. `KeywayAngle` rotates it around
  the shaft (0° is a fixed reference direction — handy for lining up
  keyways on adjacent segments). Works on any profile (Circular,
  Quadrado, Hexagonal).
- **Canal (groove)**: a full circumferential channel — `GrooveWidth` wide,
  `GrooveDepth` deep, starting at `GroovePosition`. This is a turned
  (lathe) feature, so it's only generated on **Circular** segments; on
  Quadrado/Hexagonal it's skipped with a warning in the Report view.
- **Rosca externa (external thread)**: `ThreadExtent = Total` threads the
  whole segment; `Parcial` threads only `ThreadLength`, starting from
  whichever end you pick with `ThreadSide` (Início = start, Fim = end).
  Circular profile only. **The solid itself is left alone** — no
  material is cut for the thread — and instead a **cosmetic helix
  curve** (crest + root, offset half a turn from each other) is drawn on
  the surface purely so the segment reads as threaded in the 3D view.
  Since it's a curve and not a boolean cut, its cost doesn't scale with
  pitch count or segment length, unlike cutting real thread geometry
  (which was tried and dropped for exactly that reason — see "Recent
  fixes" above). Turn `ShowThreadIndicator` off if you'd rather not see
  it at all (e.g. a very fine pitch on a long segment can make the helix
  visually busy).
- An optional **exit groove** (`HasThreadExitGroove`, DIN 76-style) can
  still be cut for real at the thread's run-out end — that's a single
  cheap boolean cut per segment, so it doesn't have the same performance
  problem as cutting full thread geometry would.
- **The 2D drawing is where the actual ISO 6410 thread indication
  lives.** `Gerar Desenho 2D (TechDraw)` (see below) draws the
  minor-diameter lines, thread-limit line, and `M8x1.25`-style
  designation directly from each segment's properties — it doesn't look
  at the 3D shape at all, so it works identically regardless of the
  `ShowThreadIndicator` setting.
- This is a **visual/DFM representation only**, not a
  manufacturing-exact ISO/UN thread profile. If you need exact thread
  geometry for machining, model the plain cylinder here and apply
  FreeCAD's built-in `PartDesign::Thread` dress-up feature (or the
  Fasteners workbench) on top.
- Need a keyway/groove at two different spots on what is otherwise one
  constant diameter? Just split it into two (or more) adjacent Segments
  of the same diameter — the Axis stacks them seamlessly either way,
  and each can carry its own keyway/groove/thread.

## Notes / possible extensions

- If you want the whole shaft as one fused solid (e.g. for export), add
  a "Fuse All" command that runs a boolean fuse over `axis.Group` shapes
  into a separate result object.
- Icons used here fall back to stock FreeCAD icons (`Std_Part`,
  `Part_Cylinder`); drop your own `.svg`/`.png` into a `Resources/icons`
  folder and point `Pixmap`/`getIcon()` at them if you want custom art.

## Notes on tree labels

Each Segment's tree label (e.g. `⌀10 x 20 - M8x1.25`) is regenerated
automatically whenever its size, length, or thread settings change. If
you rename a segment by hand, that rename sticks — the auto-label logic
only touches a segment's `Label` while it still matches the last value
*it* generated, so a manual rename is never silently overwritten on the
next recompute.

## Generating a 2D drawing with thread indication

1. Select the **Axis** (or any Segment inside it) in the Model tree.
2. Click **Gerar Desenho 2D (TechDraw)** / **Create 2D Drawing (TechDraw)**.
3. A new page is created with a front (Direction `(0,0,1)`) view of the
   whole axle. Any segment with `HasThread` enabled gets ISO 6410-style
   root-diameter lines and a thread-limit line automatically overlaid on
   top of the real geometry, plus a text legend (bottom-left of the page,
   draggable) listing each thread's designation.
4. You can add further TechDraw views (top, side, section) manually the
   same way you would for any other FreeCAD Part — this command only
   automates the front view + thread callouts.
